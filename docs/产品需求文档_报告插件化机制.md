# 产品需求文档：报告插件化机制（Report Plugin）

> 版本：v1.0（待评审）
> 日期：2026-08-06
> 状态：草案，等待确认后进入开发
> 关联：`skills/reports-engine`、`skills/master-engine`

---

## 1. 背景与问题

### 1.1 现状
JingniTrader 当前通过 `reports-engine` 生成 7 份标准报告（技术分析、基本面分析、策略回测、绩效归因、执行监控、组合优化、因子分析），采用**"模板类 + base.html.j2 统一骨架 + 集中路由"**的方式管理。

### 1.2 痛点
新增一份报告目前是**硬编码**的，需要改 3 处代码：

| 改动点 | 位置 |
|---|---|
| 在 `run()` 的路由链加一个 `if/elif` 分支 | `reports-engine/engine.py` |
| 写一个 `_run_xxx_report()` 方法（模板+数据+渲染） | `reports-engine/engine.py` |
| 在 `report_portal.py` 的 `REPORT_TYPE_CONFIG` 注册类型 | `reports-engine/scripts/report_portal.py` |

这导致：新增报告必须动主引擎代码，无法独立交付、难以并行开发、容易引入回归。

### 1.3 目标
让**新增一份报告 = 新增一个自包含的"报告插件文件夹"**，做到：

- **零改动主引擎**：不需要改 `engine.py`、`report_portal.py`。
- **自动发现**：引擎启动/运行时可扫描插件目录，自动注册。
- **自动路由**：插件声明触发条件，引擎按条件自动选中该插件生成报告。
- **自动入门户**：生成的报告自动出现在 `index.html` 门户。
- **样式统一**：插件模板继承 `base.html.j2`，自动复用统一骨架与导航/页脚。

## 2. 插件协议总览

### 2.1 插件目录结构
一份报告插件是一个自包含文件夹，放在 `reports-engine/plugins/<plugin_id>/` 下：

```
skills/reports-engine/plugins/
├── <plugin_id>/                    # 插件文件夹（如 my_report/）
│   ├── plugin.yaml                 # 插件声明（必需）：触发条件 + 所需产物 + 元数据
│   ├── render.py                   # 渲染器（必需）：统一接口 render(data, ctx, out)
│   ├── template.html.j2            # 报告模板（可选，推荐继承 base.html.j2）
│   ├── assets/                     # 插件私有资源（可选：CSS/JS/图片）
│   └── __init__.py                 # 可选，便于包导入
├── loader.py                       # 插件加载器（框架提供）
└── registry.py                     # 插件注册表（框架提供）
```

### 2.2 插件生命周期
```
启动/调用时
  loader.scan(plugins_dir)          # 扫描目录
       │
       ▼
  registry.register(plugin)         # 校验 plugin.yaml，注册到注册表
       │
       ▼
  引擎 run()                        # 遍历注册表，按 trigger 匹配
       │
       ▼
  收集 requires 产物 → 校验 data_contract → 调 render() → 写 HTML
       │
       ▼
  report_portal.upsert_report()     # 自动入门户
```

## 3. 插件声明文件 `plugin.yaml`

每个插件必须包含 `plugin.yaml`，声明插件的身份、触发条件、数据依赖与门户元信息。格式如下：

```yaml
# 插件唯一 ID（必须与文件夹名一致）
id: my_report

# 报告显示名称
label: 我的资金流报告

# 门户图标（emoji）
icon: "💧"

# 插件版本（语义化）
version: "1.0.0"

# 是否启用（默认 true）
enabled: true

# ── 触发条件（满足任一即生成；若为空则默认走"模板化个股分析"分支）──
trigger:
  # 方式一：按 ctx.metadata 字段精确匹配
  - { field: report_intent, equals: my_report }
  # 方式二：按用户意图关键词识别（与 _detect_report_template 的口径一致）
  - { keyword: ["资金流", "主力资金"] }
  # 方式三：按阶段产物存在性触发（如存在特定产物即生成）
  - { artifact: BACKTEST }

# ── 所需产物（生成前校验，缺任一即报错并跳过）──
requires:
  - DATA
  - FACTOR
  # - BACKTEST
  # - PORTFOLIO

# ── 输入数据契约（声明模板渲染需要的数据字段，防止"缺字段"隐性缺失）──
data_contract:
  # 每个所需产物的字段约束（宽松：仅声明存在性；严格：声明必填字段）
  strict: false
  FACTOR:
    required_columns: [alpha_score, momentum]
  BACKTEST:
    required_artifact: [equity_curve.parquet]

# ── 门户自动注册 ──
portal:
  enabled: true            # 是否出现在门户 index.html
  display_order: 99         # 门户排序（越大越靠后）
```

### 触发条件说明
- `trigger` 支持多规则，**满足任一即触发**。
- 优先级遵循现有 `run()` 路由链的约定：`report_intent` 精确匹配 > 关键词识别 > 产物存在性。
- 若插件不设置 `trigger`，默认归入"模板化个股分析"分支（与技术/基本面报告同级）。

## 4. 渲染器 `render.py` 统一接口

每个插件必须提供 `render.py`，实现统一的渲染入口：

```python
# render.py
def render(data: dict, ctx, output_path: str) -> str:
    """渲染报告 HTML。

    参数:
        data: 框架按 requires 收集并解析好的产物数据
              { "DATA": <price_data DataFrame>, "FACTOR": <factor_df>, ... }
        ctx:  项目的 Context 对象（含 stock_pool/benchmark/start_date 等）
        output_path: 输出 HTML 文件的完整路径（render 内部负责写入）

    返回:
        渲染后的完整 HTML 字符串（同时已写入 output_path）。
    """
    # 1. 从 data 中取所需产物，做业务计算/加工
    # 2. 调用 render_page("<plugin_id>.html.j2", **context) 渲染
    # 3. 写入 output_path
    html = render_page("my_report.html.j2", **context)
    with open(output_path, "w", encoding="utf-8") as f:
        f.write(html)
    return html

# 可选：提供 create_plugin() 工厂，便于加载器实例化带状态的插件
# def create_plugin():
#     return MyReportPlugin()
```

### 约定
- `render_page()` 由框架统一提供（`templates/common_components.render_page`），自动注入 `base_css`/`logo_svg`/`disclaimer`。
- 若插件使用 `base.html.j2` 统一骨架，`render.py` 只需组装数据 + 调 `render_page`。
- 若插件需要完全自定义页面（如全屏大屏），可 `base_css=""` + 在 `head_css` 提供专属样式（与现有技术/基本面报告的做法一致）。

## 5. 模板 `template.html.j2`

插件模板继承 `base.html.j2`，复用统一骨架。示例：

```jinja
{% extends "base.html.j2" %}

{% block title %}{{ stock_name }} 资金流分析报告{% endblock %}

{% block head_css %}
/* 插件专属样式（可选） */
{% endblock %}

{% block content %}
{{ page_header(title, subtitle) }}

{% call section_block("主力资金流向") %}
  {{ metric_card(main_inflow, "主力净流入", "positive") }}
{% endcall %}

{% for chart_html in charts %}
<div class="section"><div class="chart-container">{{ chart_html | safe }}</div></div>
{% endfor %}
{% endblock %}
```

### base.html.j2 已提供的公共组件
| 宏 | 作用 |
|---|---|
| `nav_bar(report_title)` | 顶部导航栏 |
| `page_header(title, subtitle)` | 正文标题 header |
| `metric_card(value, label, cls)` | 指标卡片 |
| `section_block(title)` + `{% call %}` | 章节区块 |
| `footer_block(disclaimer)` | 免责声明 + 版权 footer |

### 6.3 校验规则
- `plugin.yaml` 缺失 / 格式错误 → 记录 warning，跳过该插件，不影响其它插件。
- `id` 与文件夹名不一致 → 以文件夹名为准并告警。
- 缺少 `render.py` → 记录 error，跳过。
- `requires` 中声明的产物在当前 `ctx` 缺失时，该插件不会被触发（除非 `trigger` 只按关键词）。

## 7. 引擎集成改造（`reports-engine/engine.py`）

### 7.1 改造目标
把 `run()` 里的**硬编码 if/elif 路由**改为**遍历插件注册表**，同时保留现有 7 份报告作为"内置插件"。

```
改造前（硬编码）:
  if report_intent == "attribution": ...
  elif report_intent == "portfolio": ...
  elif report_intent == "execution": ...
  elif has BACKTEST: ...
  else: _run_template_report()   # 技术/基本面

改造后（插件化）:
  plugins = registry.find_by_trigger(ctx)      # 匹配插件（含内置）
  if plugins:                                   # 优先命中插件
      return _run_plugin(ctx, plugins[0])
  else:
      return _run_template_report(ctx)          # 兜底技术/基本面
```

### 7.2 内置插件化
现有 7 份报告**逐步迁入** `plugins/` 作为内置插件：
- 每个报告拆成 `plugin.yaml` + `render.py` + `template.html.j2`。
- 迁移时**保持渲染逻辑与测试不变**，仅套插件协议。
- 迁移完成前，内置报告仍走原硬编码路由，与插件机制**并行兼容**。

### 7.3 并行兼容策略
- 插件机制上线后，内置报告可**选择性迁移**（不强制一次全部迁）。
- 新增报告走插件机制；存量报告保留原路径，后续逐个迁移。
- 引擎提供 `ENABLE_PLUGIN` 开关（环境变量），可平滑启停插件机制，降低灰度风险。

## 8. 开发一个报告插件的完整步骤（示例：资金流报告）

**目标**：新增"资金流报告"，当用户说"分析 X 的资金流"时自动生成。

### 步骤 1：创建插件文件夹
```
skills/reports-engine/plugins/capital_flow_report/
├── plugin.yaml
├── render.py
└── template.html.j2
```

### 步骤 2：编写 `plugin.yaml`
```yaml
id: capital_flow_report
label: 资金流分析
icon: "💧"
version: "1.0.0"
trigger:
  - { keyword: ["资金流", "主力资金", "北向资金"] }
requires:
  - DATA
data_contract:
  strict: false
portal:
  enabled: true
  display_order: 20
```

### 步骤 3：编写 `template.html.j2`
继承 base.html.j2，展示主力净流入、北向资金、板块资金等。

### 步骤 4：编写 `render.py`
```python
from templates.common_components import render_page

def render(data, ctx, output_path):
    price_df = data["DATA"]
    # ... 计算资金流指标 ...
    html = render_page("capital_flow_report.html.j2",
                       main_inflow="1.2亿", north_inflow="3000万",
                       title=f"{ctx.stock_pool[0]} 资金流分析")
    with open(output_path, "w", encoding="utf-8") as f:
        f.write(html)
    return html
```

### 步骤 5：验证
```bash
python -m pytest tests/reports_engine/            # 全量回归
python engine.py -i "分析 002594.SZ 的资金流"       # 触发新插件
```
- 用户输入"资金流"→ 引擎按关键词匹配到 `capital_flow_report` 插件 → 生成 `capital_flow_report.html` → 自动出现在门户。

## 9. 验收标准（Acceptance Criteria）

1. **零代码接入**：在 `plugins/` 下新增一个含 `plugin.yaml` + `render.py` + `template.html.j2` 的文件夹，无需修改 `engine.py`/`report_portal.py`，即可被引擎识别、路由并生成报告。
2. **触发匹配**：插件能通过 `report_intent` 字段、关键词、产物存在性三种方式之一被触发。
3. **数据契约校验**：插件声明的 `requires`/`data_contract` 缺失时，给出明确警告并跳过，不崩溃。
4. **统一样式**：插件模板继承 `base.html.j2`，输出报告含统一导航/页脚/免责声明。
5. **自动入门户**：生成的报告自动出现在 `index.html`，且 `plugin.yaml` 的 `icon`/`label`/`display_order` 生效。
6. **兼容存量**：现有 7 份报告在插件机制开启后仍能正常生成，`tests/reports_engine/` 全部通过。
7. **隔离失败**：单个插件 `plugin.yaml` 或 `render.py` 异常不影响其它插件与内置报告。
8. **重载生效**：新增/修改插件后，无需重启进程，调用一次 `loader.reload()` 即可生效。

## 10. 风险与后续迭代

### 10.1 风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| 内置 7 份报告迁移工作量大 | 迁移期回归 | 并行兼容 + 分步迁移 + 全量测试 |
| 插件触发条件与现有路由冲突 | 报告误选 | 明确优先级规则 + 测试覆盖 |
| 数据契约校验过严 | 合法插件被误拒 | `strict: false` 默认宽松，仅告警 |
| 动态导入安全 | 恶意插件执行 | 仅加载项目内 `plugins/` 白名单目录 |

### 10.2 后续迭代方向
- **插件市场/目录页**：门户展示所有可用插件及其说明。
- **插件参数化**：`plugin.yaml` 支持自定义参数，供 `render.py` 读取。
- **插件依赖管理**：声明第三方依赖（如 `requires_python`/`pip_packages`）。
- **多模板插件**：一个插件支持多种 `template.html.j2` 布局。
- **数据预处理钩子**：插件可声明 `preprocess` 钩子，在渲染前加工产物。

| 现有机制 | 插件化后的角色 |
